# КомуналОчка · Львів

Український вебзастосунок для особистого обліку п’яти комунальних послуг у Львові. Сучасний адаптивний інтерфейс, автоматичний підсумок, збереження чернеток за місяцями та окремі тарифи для кожного помешкання.

## Швидкий запуск

Сайт: [komunalochka.com](https://komunalochka.com). Калькулятор і підготовка показників доступні без реєстрації. Для безкоштовного Premium увійдіть через ChatGPT та активуйте промокод або подайте заявку.

Для повного локального запуску потрібні Node.js 24 (мінімум 22.13) та npm:

```sh
cd komunalochka-lviv
npm ci
npm run build
# Лише для нового локального сховища; не запускайте повторно на тій самій БД.
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_vengeful_sentinel.sql
npm run dev -- --port 4173 --hostname 127.0.0.1
```

Відкрийте [http://127.0.0.1:4173](http://127.0.0.1:4173). Зупинка — `Ctrl+C`. Локальний шаблон Sites імітує вхід як `seedy@sites.test`; це не виробничий користувач. Для перевірки локальної адмінпанелі додайте в ігнорований `.dev.vars` рядок `PREMIUM_ADMIN_EMAIL=seedy@sites.test` і перезапустіть сервер. У виробничій збірці ця імітація вимкнена.

Після перенесення на інший домен розрахунки потрібно перенести через JSON-копію: localStorage прив’язаний до адреси сайту. Вхід відновлює право на Premium, а не локальні показники.

1. Оберіть місяць.
2. У розділі **Тарифи** звірте базові ставки. Увімкніть **Власні тарифи**, щоб редагувати їх. Для сміття введіть ставку вашого перевізника.
3. Внесіть попередні й поточні показники, річну потужність доставки газу та кількість мешканців. Вимкніть послуги, яких немає у вашому помешканні.
4. Чернетка зберігається після кожної зміни. **Зберегти розрахунок** створює запис місяця з копією показників і тарифів.
5. Кнопка **Спробувати на прикладі** після підтвердження заповнює демонстраційні дані. Це явна заміна поточної чернетки; ставка сміття 45 грн у прикладі умовна.

## Стек та архітектура

Калькулятор зберігає Vanilla HTML5, CSS3 та JavaScript. Серверні маршрути працюють через Vinext/Vite у Cloudflare Worker на Sites, а права Premium, заявки та хеші промокодів — у D1 (SQLite). Авторизація використовує вбудований вхід Sites через ChatGPT. Вебшрифт Manrope має системний запасний варіант.

```text
index.html, styles.css, app.js    Калькулятор, тарифи, історія й передача показників
premium.js                       Вхід, промокод, заявка та перевірка доступу
admin.html, admin-panel.js,
admin.css                        Панель власника /admin
app/                             Серверні HTML- та API-маршрути Vinext
server/premium.mjs               Авторизація, бізнес-правила та SQL-запити Premium
db/schema.ts, drizzle/           Схема D1 та версійована міграція
build/, scripts/                 Інтеграція Sites, підготовка ресурсів та збірка
tests/                           Тести розрахунків, SQL, API та браузерні сценарії
.openai/hosting.json              Наявний проєкт Sites та прив’язка D1 DB
```

`app.js` ізольований у функції; чисте ядро доступне як `window.KomunalCore`. Навігація використовує `#dashboard`, `#tariffs`, `#history`, `#profiles`, `#transfer`. Сервер не отримує показники з калькулятора.

Схема localStorage `komunalochka.lviv.v1` зберігає помешкання, чернетки за місяцями, тарифи, історію, тему, реквізити та журнали передачі. Історія містить знімок тарифів, тому їх зміна не переписує стару квитанцію. Повторне збереження місяця потребує підтвердження. Схема сумісна з попередніми даними; старе поле `activationKey` ігнорується й не надає Premium.

## Два режими перегляду

Кнопка **Aa Вигляд** у верхній панелі відкриває вибір:

- **Стандартний** — початковий компактний інтерфейс.
- **Зручний перегляд** — текст переважно 18 px, показники 24 px, великі кнопки від 54 px, помітні підписи, контрастніший текст, просторі картки, коротка інструкція з трьох кроків. На телефоні поля розташовані одне під одним.

Обидва режими доступні без входу та Premium. Вибір застосовується одразу, зберігається в окремому ключі localStorage `komunalochka.view-mode.v1` та синхронізується між вкладками. Він поширюється на калькулятор, тарифи, передачу показників, Premium і адмінпанель. Показники, тарифи та права доступу не змінюються. Якщо браузер забороняє запис у сховище, режим працює до закриття вкладки й показує пояснення. Підтримуються клавіатура, Escape та повернення фокусу; формат друку A4 збережено.

Реалізація: `view-mode.js` застосовує перевагу до першого відображення сторінки, `view-mode.css` містить окремі стилі. Повернутися до початкового вигляду можна тією самою кнопкою.

## Формули

| Послуга | Розрахунок |
| --- | --- |
| Газ | `(поточний − попередній), м³ × тариф` |
| Вода та водовідведення | `(поточний − попередній), м³ × сумарний тариф` |
| Електроенергія, одна зона | `(поточний − попередній), кВт·год × денний/базовий тариф` |
| Електроенергія, дві зони | `денне споживання × денний тариф + нічне × нічний тариф` |
| Доставка газу | `річна замовлена потужність, м³ ÷ 12 × тариф за м³ місячної потужності` |
| Сміття | `тариф за особу на місяць × зареєстровані мешканці` |

Для доставки вводиться **річна замовлена потужність із рахунку оператора**, а не поточне споживання газу. Якщо у рахунку наведена лише місячна потужність, помножте її на 12. Мінімальну замовлену потужність калькулятор самостійно не визначає.

Усі тарифи вводяться **з ПДВ**. Кожна послуга округлюється до копійок, загальна сума — сума цих значень. Проміжна місячна потужність не округлюється. Нульові обсяги допустимі. Порожні значення не перетворюються на нулі; частковий підсумок позначається. Від’ємні числа, зворотні показники, дробові мешканці, експоненти, некоректні символи та суми понад ліміт відхиляються. Підтримуються кома й крапка та до 6 десяткових знаків; вводьте числа без розділювачів тисяч.

Спеціальні пільгові схеми електроопалення, три зони, опалення, утримання будинку, абонплата, борги, субсидії та пільги не входять у розрахунок. Квитанція є особистим розрахунком, не підтвердженням оплати.

## Передача показників через офіційні форми

Функція доступна **без Premium** у меню **Передати показники**, із підсумку та з карток газу, води й електрики. Оберіть вкладку послуги; вона має власні реквізити й журнал у кожному помешканні.

| Послуга | Офіційний сервіс і реквізити | Показники |
| --- | --- | --- |
| Газ | [«Газмережі»](https://my.grmu.com.ua/login): 10-значний рахунок із платіжки за доставку. [Нафтогаз](https://gas.ua/uk/indicators): окремий 9-значний рахунок за газ, перші три літери прізвища й український телефон | Накопичені цілі м³ |
| Вода | [InfoLviv](https://infolviv.com.ua/) — персональний кабінет, на який веде [офіційний сайт Львівводоканалу](https://lvivvodokanal.com.ua/). Особовий рахунок із платіжки; номер водоміра можна додати для зручності | Накопичені м³; до 6 десяткових знаків без мовчазного округлення. Допустиму точність звірте в кабінеті |
| Електрика | [Форма Львівобленерго без реєстрації](https://loe.lviv.ua/send-pokaz) або [кабінет](https://info.loe.lviv.ua/). Потрібен 10-значний код Львівобленерго з рахунку; це не EIC-код і не заводський номер приладу | Цілі кВт·год: одна зона або окремі накопичені регістри «день» і «ніч» |

1. Оберіть послугу й сервіс, внесіть реквізити, дату та місяць обліку. Початкові нулі рахунку зберігаються. Для води й електрики можна додати номер лічильника; він допомагає обрати прилад у кабінеті, але не замінює рахунок.
2. Перевірте показники з калькулятора обраного місяця. Зміни тут зберігаються і в його чернетці. Подаються **накопичені показники**, а не різниця за місяць. Попередні значення необов’язкові, якщо вони вже є в офіційному кабінеті. Тип електрообліку синхронізований із калькулятором; для двох зон потрібні обидва поточні показники, вони не сумуються.
3. Натисніть **Підготувати передачу**. Перевірте незмінний знімок, скопіюйте значення окремо або все разом. Якщо буфер недоступний, з’явиться поле для ручного копіювання.
4. Відкрийте офіційний сервіс, за потреби увійдіть, оберіть рахунок та потрібний прилад, перенесіть значення і **завершіть відправлення на офіційному сайті**. Якщо водомірів кілька, внесіть показник кожного у відповідне поле кабінету. Автозаповнення чужої сторінки, обхід входу чи CAPTCHA не виконуються.
5. Після підтвердження прийняття поверніться та натисніть **Я отримав підтвердження на сайті**. Поставте явну відмітку; за бажанням збережіть номер або примітку підтвердження.

За [повідомленням Львівобленерго](https://loe.lviv.ua/news/6047), показники за місяць приймаються в останні два дні місяця та до 3 числа наступного. Періоди й доступність інших сервісів перевіряйте на їхніх сторінках.

**Доставка газу** не має окремого показника: подавайте показник газового лічильника у вкладці «Газ», доставка обчислюється за замовленою потужністю. **Вивіз сміття** не має лічильника; зміну кількості мешканців узгоджують із перевізником.

Журнал розрізняє **Підготовлено**, **Перехід до форми** та **Позначено вами як передане**. Жоден із цих статусів не видається за автоматичне підтвердження провайдера. Натискання посилання саме по собі не надсилає показники; дані не додаються до URL чи HTTP-запиту переходу. Паролі та SMS-коди вводяться лише в офіційному сервісі.

Підготовка однакових даних повторно відкриває той самий запис. Зміна показника створює інший знімок, не переписуючи попередні. Кожна з трьох послуг у кожному помешканні має власний журнал до 200 записів. Запис видаляється після підтвердження. Очищення реквізитів впливає лише на обрану послугу й не видаляє знімки журналу — їх можна видалити окремо.

Схема localStorage залишається `v1`. Наявні газові налаштування та записи зберігаються, відсутні `gasTransfer`, `waterTransfer` чи `electricityTransfer` отримують порожні налаштування. Розрахунки й історія не скидаються. При імпорті перевіряються значення, відповідність послузі, статуси, дати, порядок подій та унікальні ID. Прямий API надсилання не підключений; погоджений сценарій використовує офіційні форми.

### Онлайн-перевірка та fallback

При першому відкритті й за кнопкою **Перевірити онлайн** застосунок паралельно виконує запити `fetch` до офіційних сторінок Нафтогазу, Львівводоканалу та Львівобленерго. Кожен запит має тайм-аут 6,5 секунди. Сторінки розбираються як текст; їхні скрипти не виконуються. Консервативні адаптери шукають підписані побутові тарифи й відкидають неоднозначні відповіді та оптові ставки.

Багато постачальників забороняють CORS або показують тарифи лише після виконання JavaScript. У такому разі статус прямо повідомляє про недоступність, ставки залишаються незмінними, а **Власні тарифи** завжди доступні без Premium. Не використовується сторонній CORS-проксі.

Знайдені значення є **пропозиціями**, а не автоматичним підтвердженням чинності. Перевірте дату дії в джерелі, натисніть **Застосувати знайдені ставки**; це ввімкне власний режим і збереже ставки в поточному помешканні. Нічна ставка не виводиться автоматично з денної. Неправильне введення в редакторі показує помилку й не перезаписує останню коректну збережену ставку.

Для надійного промислового оновлення потрібен окремий контрольований серверний адаптер із перевіркою формату, періоду та категорії споживача. Перевірка тарифів виконується у браузері; сервер Premium не є проксі постачальників.

## Premium

Без активації доступні всі п’ять розрахунків, ручні тарифи, збереження чернеток і місячних записів, підготовка передачі газових, водяних та електричних показників з окремими журналами. За замовчуванням Premium-функції заблоковані:

- **Історія й графіки**: доступний SVG-графік останніх 12 фактично збережених місяців. Перемикання між гривнями, кВт·год і м³. Є таблиця, відновлення показників, PDF і видалення запису після підтвердження. Пропущені місяці не підміняються нулями.
- **До 5 помешкань**: назва, адреса у Львові, окремі чернетки, тарифи й історія. Видалення потребує підтвердження.
- **Квитанція у PDF**: охайний шаблон A4 з формулами, тарифами та сумами через системний друк. У діалозі браузера виберіть **Зберегти як PDF**. Це не пряме завантаження готового PDF-бінарника.
- **Персональні поради**: прозорі локальні сценарії економії води та електроенергії, порівняння із збереженим місяцем. Зовнішнього ШІ та гарантованої економії немає.
- **Темна тема**: перемикається кнопкою місяця у верхній панелі та зберігається.
- **JSON-копії**: експорт і відновлення після перевірки схеми. Поточні дані замінюються лише після підтвердження. Імпорт перераховує історичні підсумки замість довіри до довільного поля `total`.

### Безкоштовна активація

1. Натисніть **Відкрити Premium** та увійдіть через ChatGPT.
2. Вставте отриманий промокод формату `XXXX-XXXX-XXXX-XXXX` або відкрийте вкладку **Подати заявку** й коротко поясніть потребу.
3. Після схвалення статус з’явиться в цьому ж вікні. Кнопка перевірки рішення оновлює його одразу; активна вкладка також перевіряє стан щохвилини.

Промокоди створює власник. Загальнодоступних постійних ключів у вихідному коді немає; старі демонстраційні ключі більше не діють. Новий код показується власнику **один раз**. Сервер зберігає лише SHA-256-хеш, назву, ліміт активацій та строки. Один акаунт може використати код один раз. Відкликання конкретного доступу не дозволяє повторно активувати той самий код.

### Панель власника

Відкрийте [komunalochka.com/admin](https://komunalochka.com/admin) та увійдіть тим самим акаунтом ChatGPT, який володіє сайтом. Власник автоматично отримує Premium.

- **Заявки**: схвалити або відхилити, додати примітку, видати доступ на 30/365 днів або безстроково.
- **Промокоди**: згенерувати код, визначити кількість активацій, строк дії коду та тривалість доступу; вимкнути чи знову ввімкнути нові активації.
- **Доступ**: переглянути видані права, подовжити або відкликати їх.

Вимкнення коду не забирає вже виданий доступ — для цього використовуйте вкладку **Доступ**. Надсилання email не підключене: користувач бачить рішення в особистому вікні Premium.

Сервер перевіряє довірену ідентичність Sites і секрет `PREMIUM_ADMIN_EMAIL`. Публічна HTML-оболонка `/admin` не дає доступу до даних: усі адміністративні API перевіряють власника. Клієнтський прапорець чи імпорт JSON не надає серверних прав. Застосунок залишається відкритим кодом; локальні графіки й теми можна відтворити зі зміненого клієнта — це не DRM.

### Виробничі налаштування

Значення задаються через Sites environment variables, а не у Git:

- `PREMIUM_ADMIN_EMAIL` — секретна підтверджена адреса власника.
- `PREMIUM_ALLOWED_ORIGINS` — через кому: `https://komunalochka.com,https://www.komunalochka.com,https://komunalochka-lviv.ableolm64.chatgpt.site`.

D1 прив’язаний як `DB`. Sites застосовує міграції з `drizzle/` під час публікації. Після зміни схеми створюйте нову міграцію (`npm run db:generate`), не редагуйте вже застосовану. Секрети та `.dev.vars` не комітяться.

Записи Premium містять ідентифікатор, ім’я й email акаунта, заявки, рішення та права доступу. Коди активуються атомарно з лічильником використань; паралельні запити не перевищують ліміт. API перевіряє Origin, JSON, спеціальний заголовок та обмеження розміру; є обмеження спроб і частоти заявок. При втраті зв’язку стан доступу перевіряється повторно, локальні розрахунки не видаляються.

## Дані та стійкість

- «КомуналОчка» автоматично не надсилає показники, адреси чи реквізити постачальникам: запитуються лише їхні публічні сторінки. Користувач сам переносить підготовлені дані в офіційну форму й відправляє їх там. Немає аналітики чи зовнішнього ШІ. Google Fonts отримує стандартний запит браузера для шрифту.
- localStorage не шифрується; користувачі цього браузера можуть прочитати дані. JSON-копія містить також особові рахунки, номери лічильників, телефон, літери прізвища та журнали передачі, якщо їх внесено. Зберігайте копію у себе.
- Помилка доступу/квоти відображається явно. Застосунок продовжує обчислення в пам’яті, але не заявляє, що зміни збережені. Пошкоджений попередній запис не перезаписується автоматично.
- Дані імпорту перевіряються: версія, місяці, типи полів, унікальні помешкання та місяці, ліміти, завершені розрахунки. Максимум — 5 МБ на файл, 5 помешкань, місяці 2020–2100.
- Користувацький текст екранується перед додаванням у HTML. Імпорт не виконує HTML або JavaScript.
- Інші вкладки отримують зміни через подію `storage`. Одночасне редагування не має серверного вирішення конфліктів: останнє збереження є поточним.
- Підтримуються підписи полів, клавіатурний фокус, нативні діалоги, live-повідомлення, режим зменшення анімації та мобільна навігація.

## Перевірка та збірка

```sh
npm test                  # 21 тест калькулятора + 9 тестів Premium/SQL
npx tsc --noEmit
npm run build             # Worker у dist/server та ресурси у dist/client
```

`node scripts/build.mjs` запускає ту саму повну збірку. Потрібні встановлені залежності. Для браузерних перевірок використайте доступний Playwright і Chromium; якщо пакета немає: `npm install --no-save --package-lock=false playwright`, `npx playwright install chromium`. Локальний сервер має працювати на порту 4173:

```sh
TEST_URL=http://127.0.0.1:4173 BROWSER_CHANNEL=chrome npm run test:browser
TEST_URL=http://127.0.0.1:4173 BROWSER_CHANNEL=chrome npm run test:transfer
TEST_URL=http://127.0.0.1:4173 BROWSER_CHANNEL=chrome npm run test:networks
TEST_URL=http://127.0.0.1:4173 BROWSER_CHANNEL=chrome npm run test:view
# Тільки одноразова локальна БД з синтетичними даними, ніколи --remote:
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file tests/premium-seed.sql
TEST_URL=http://127.0.0.1:4173 BROWSER_CHANNEL=chrome npm run test:premium
```

Для іншої інсталяції Playwright можна передати `PLAYWRIGHT_MODULE_PATH`. Premium E2E змінює лише локальну тестову БД і відхиляє виробничий URL. Перед повторним запуском цього набору повторіть локальне заповнення `tests/premium-seed.sql`. Інші E2E використовують контрольовані відповіді API. Реальних показників постачальникам вони не надсилають. Знімки та результати ігноруються Git; фактичні перевірки описані в `VERIFICATION.md`.

## GitHub та публікація

Репозиторій: [indozer777/komunalochka-lviv](https://github.com/indozer777/komunalochka-lviv). Для оновлення наявного каталогу:

```sh
git add .
git commit -m "Update KomunalOchka"
git push origin main
```

Для окремого нового репозиторію без історії (не запускайте повторно для вже створеного):

```sh
gh auth login
git init -b main
git add .
git commit -m "Initial commit: Lviv utility calculator"
gh repo create komunalochka-lviv --public --source=. --remote=origin --push
```

Повний застосунок працює на Sites: збірка, push у прив’язаний source-репозиторій, збереження версії та публікація цієї версії. Використовуйте існуючий `project_id` з `.openai/hosting.json`. Домен і публічний доступ зберігаються. Сам push у GitHub не публікує Worker.

GitHub Pages або простий HTTP-сервер можуть показати кореневий калькулятор, але серверні Premium, вхід, заявки та адмінпанель потребують Worker і D1. Для повної версії використовуйте `https://komunalochka.com`, а не статичну копію.
